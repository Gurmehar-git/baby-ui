# Laws, each with its UI check

| Law | Check |
| --- | --- |
| Fitts | Primary targets large and close to where attention is; 24px minimum, 44px on touch |
| Hick | Choices per decision about 7 or fewer; a default preselected |
| Miller / chunking | Group long content into chunks of about 4 |
| Jakob | Familiar placement and keys: Escape closes, Enter submits, close top-right |
| Doherty | Feedback within 100ms; results within 400ms or a progress state |
| Peak-end | The completing moment (success, done) is the most polished |
| Von Restorff | One element stands out per view, and it is the one that matters |
| Gestalt | Proximity groups, similarity means same behaviour, continuity guides the eye |
| Tesler | The component absorbs complexity (formatting, validation), not the user |
| Postel | Accept loose input (paste, spaces in card numbers), output strict |
| Goal gradient | Progress toward done is visible and accelerates near the end |
| Zeigarnik | Unfinished tasks stay visible until done |
| Aesthetic-usability | Polish earns patience, never at the cost of clarity |
| Cognitive load | No decoration that doesn't inform; recognition over recall |
| Forgiveness | Undo or confirm destructive actions; errors recoverable in place |
| Ethics | No dark patterns: equal accept and reject, no confirmshaming, no pre-ticked consent |
